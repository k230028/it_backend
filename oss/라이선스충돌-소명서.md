# 오픈소스 라이선스 충돌 소명서

| 항목 | 내용 |
| --- | --- |
| 대상 | IT Project Portal 백엔드 (`com.kdb:it`, WAR 배포) |
| 점검 결과 | 라이선스 충돌 11건 (정책 필터링 1건, "조치 필요" 10건) |
| 작성일 | 2026-07-22 |
| **결론** | **"조치 필요" 10건 전부 점검 도구의 오탐이며, 실제 라이선스 충돌은 존재하지 않습니다. 의존성 교체 없이 사용허가를 요청합니다.** |

---

## 1. 요약

점검 결과에 제기된 충돌은 두 가지 도구 한계에서 비롯된 것으로, 실제 배포 산출물에는 해당 충돌이 존재하지 않습니다.

1. **컴포넌트 버전 오인식** — 실재하지 않는 `jakarta.persistence-api 4.0.0-M6`(마일스톤)을 사용 중인 것으로 식별했습니다. 실제 사용 버전은 `3.2.0`이며, 이 버전에는 충돌의 근거가 된 **Eclipse Public License 1.0이 포함되어 있지 않습니다.**
2. **선택적(OR) 이중 라이선스를 동시 적용(AND)으로 오해석** — `jakarta.annotation-api 3.0.0`은 EPL 2.0 **또는** GPL2 w/CPE 중 하나를 선택하는 구성입니다. 도구가 두 라이선스를 동시 적용으로 처리하여 존재하지 않는 충돌을 생성했습니다.

이 두 가지를 보정하면 "조치 필요" 10건이 모두 해소됩니다.

## 3. 오탐 원인 ① — 컴포넌트 버전 오인식

### 3.1 사실관계

점검 결과는 `jakarta.persistence-api 4.0.0-M6`을 사용 컴포넌트로 식별하고, 여기에 Eclipse Public License 1.0을 부여했습니다. 그러나 해당 버전은 본 시스템 어디에도 존재하지 않습니다.

| 확인 지점 | 실제 값 |
| --- | --- |
| 배포 WAR 내 실물 jar | `WEB-INF/lib/jakarta.persistence-api-**3.2.0**.jar` |
| 폐쇄망 반입 미러 | `3.2.0` 단일 버전만 존재 |
| Gradle 의존성 캐시 | `3.2.0` 단일 버전만 존재 |
| 반입 컴포넌트 목록 (`전체목록.csv` 92행) | `jakarta.persistence-api`, `3.2.0` |

### 3.2 실제 사용 버전의 라이선스

`jakarta.persistence-api 3.2.0`의 POM이 선언한 라이선스 원문입니다.

```xml
<licenses>
    <license>
        <name>Eclipse Public License v. 2.0</name>
        <url>http://www.eclipse.org/legal/epl-2.0</url>
    </license>
    <license>
        <name>Eclipse Distribution License v. 1.0</name>
        <url>http://www.eclipse.org/org/documents/edl-v10.php</url>
    </license>
</licenses>
```

**Eclipse Public License 1.0은 선언되어 있지 않습니다.** EDL 1.0은 BSD-3-Clause 계열의 허용적(Permissive) 라이선스입니다.

따라서 **"Eclipse Public License 1.0"을 근거로 제기된 4건의 충돌은 전제가 성립하지 않습니다.**

### 3.3 오인식이 발생한 경위

점검 도구가 빌드 산출물이 아닌 `build.gradle` **텍스트를 파싱**한 것으로 판단됩니다. 해당 선언은 Spring Boot BOM이 버전을 관리하므로 원래 버전이 비어 있었고, 도구가 이를 자체 DB의 최신값(마일스톤 `4.0.0-M6`)으로 대체한 것으로 보입니다.

```gradle
// 조치 전 (버전 미지정 — BOM 관리)
annotationProcessor 'jakarta.persistence:jakarta.persistence-api'
annotationProcessor 'jakarta.annotation:jakarta.annotation-api'
```

텍스트 파싱임을 뒷받침하는 정황은 다음과 같습니다.

- 점검 결과에 컴포넌트명이 **`${project.artifactId} 3.0.3`** 으로 기재되어 있습니다. 이는 springdoc POM의 `<name>${project.artifactId}</name>` 속성이 치환되지 않은 문자열로, 바이너리(jar) 분석에서는 산출될 수 없는 값입니다.
- 식별된 컴포넌트 총계가 **24개**(Apache 17 + EPL 2.0 3 + MIT 2 + EPL 1.0 1 + GPL2 w/CPE 1)인 반면, 실제 배포 WAR에 동봉된 jar는 **110개**입니다. 직접 선언된 의존성만 분석 대상이 된 것으로 보입니다.
- MIT 2건은 `jsoup`과 `Lombok`으로 확인되나, **Lombok은 `compileOnly` 스코프라 배포 WAR에 포함되지 않습니다**(WAR 내 검색 결과 0건). 배포되지 않는 컴포넌트가 배포 라이선스 충돌 대상에 포함되어 있습니다.

## 4. 오탐 원인 ② — 선택적(OR) 이중 라이선스의 동시 적용 오해석

### 4.1 사실관계

`jakarta.annotation-api 3.0.0`의 POM 선언 원문입니다.

```xml
<licenses>
    <license>
        <name>EPL 2.0</name>
        <url>https://www.eclipse.org/legal/epl-2.0</url>
    </license>
    <license>
        <name>GPL2 w/ CPE</name>
        <url>https://www.gnu.org/software/classpath/license.html</url>
    </license>
</licenses>
```

이는 Jakarta EE 규격 API가 공통으로 채택한 **선택적 이중 라이선스(dual license, disjunctive)** 로, 이용자가 둘 중 하나를 **선택**하여 적용합니다. Maven POM 규격에는 AND/OR를 구분하는 표기가 없어, 다수 점검 도구가 복수 `<license>` 항목을 관행적으로 동시 적용(AND)으로 처리합니다.

### 4.2 점검 결과 자체에 나타난 논리적 모순

점검 결과 3번째 행은 다음과 같습니다.

- Based License (EPL 2.0) 측 컴포넌트: **"Jakarta Annotations API 3.0.0 외 2개"**
- Conflicted License (GPL2 w/CPE) 측 컴포넌트: **"Jakarta Annotations API 3.0.0"**

**동일한 단일 컴포넌트가 충돌의 양쪽 당사자로 기재되어, 자기 자신과 충돌하는 것으로 판정되었습니다.** 이는 선택적 이중 라이선스를 동시 적용으로 오해석했음을 직접적으로 보여줍니다.

### 4.3 당사 적용 라이선스 선언

당사는 `jakarta.annotation-api 3.0.0`에 대하여 **Eclipse Public License 2.0을 선택 적용**합니다. 이에 따라 GPL2 w/CPE 조항은 적용되지 않으며, **GPL2 w/CPE를 근거로 제기된 4건의 충돌은 성립하지 않습니다.**

## 5. 보강 논거

### 5.1 Classpath Exception에 의한 전파 차단

설령 GPL2 조항을 검토하더라도, 본 컴포넌트의 GPL2에는 **Classpath Exception(CPE)** 이 부가되어 있습니다. CPE는 독립 모듈과의 링크 및 결합물 배포를 GPL 의무에서 명시적으로 면제하므로, Apache License 2.0 및 MIT 컴포넌트로 카피레프트 의무가 전파되지 않습니다. 이는 Jakarta EE 전 규격 API가 채택한 표준 구성입니다.

### 5.2 배포 형태가 단순 취합(aggregation)에 해당

본 시스템은 각 오픈소스 컴포넌트를 **수정하지 않은 jar 상태 그대로** WAR의 `WEB-INF/lib/`에 동봉하여 동적 링크 방식으로 사용합니다.

- EPL 2.0은 **파일 단위 약한 카피레프트(weak/file-level copyleft)** 로, 수정된 EPL 파일에 한하여 소스 공개 의무가 발생합니다. 당사는 어떠한 EPL 컴포넌트도 수정하지 않았습니다.
- "Apache License 2.0과 EPL 2.0의 비호환"은 양자를 **하나의 저작물로 결합하여 단일 라이선스로 재배포**하는 경우의 쟁점이며, 개별 컴포넌트를 원형 그대로 취합 배포하는 본 사례에는 해당하지 않습니다.

## 7. 조치 내역

### 7.1 빌드 구성 보정 (완료)

재점검 시 버전 오인식이 재발하지 않도록 `build.gradle`에 버전을 명시 고정했습니다.

```gradle
annotationProcessor 'jakarta.persistence:jakarta.persistence-api:3.2.0'
annotationProcessor 'jakarta.annotation:jakarta.annotation-api:3.0.0'
```

고정한 값은 Spring Boot 4.1.0 BOM의 해석 결과와 동일하여 **런타임 동작 변화가 없습니다.**

```
$ ./gradlew dependencies --configuration annotationProcessor
조치 전: jakarta.persistence:jakarta.persistence-api  -> 3.2.0
        jakarta.annotation:jakarta.annotation-api    -> 3.0.0
조치 후: jakarta.persistence:jakarta.persistence-api:3.2.0
        jakarta.annotation:jakarta.annotation-api:3.0.0
```

### 7.2 재점검 입력 자료 변경 (요청)

근본 원인이 빌드 스크립트 텍스트 파싱에 있으므로, 재점검 시 다음 중 하나를 입력으로 사용해 주시기를 요청합니다.

1. **빌드 산출물 WAR 실물** (`it-0.0.1-SNAPSHOT.war`) — 가장 정확
2. **확정 컴포넌트 목록** `it_backend/oss/전체목록.csv` — 그룹/아티팩트/버전이 확정된 410건

## 9. 결론
