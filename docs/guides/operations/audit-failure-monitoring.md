# 감사로그 저장 실패 모니터링 가이드 (ERR-06)

감사로그(`@LogTarget` 엔티티의 변경 이력)는 원 업무 커밋 이후 별도 트랜잭션에서 저장됩니다.
이 저장이 실패해도 원 업무는 롤백되지 않으므로, 실패는 조용히 누적될 수 있습니다.
`AuditFailureRecorder`가 모든 감사 쓰기 실패를 Micrometer 카운터와 ERROR 로그로 기록하므로,
아래 지표를 지속 모니터링해 감사 누락을 탐지합니다.

## 메트릭

- **카운터 이름**: `audit.log.write.failure`
- **의미**: 감사로그 INSERT/스케줄링이 실패할 때마다 1 증가합니다.
- **분류 태그** (값 종류가 제한된 항목만 사용, PK·PII 미포함):

  | 태그 | 의미 | 예시 값 |
  | ---- | ---- | ------- |
  | `entity` | 감사 대상 업무 엔티티 종류 | `Bprojm`, `Bplana` |
  | `chgTp` | 변경 유형 | `C`(생성), `U`(수정), `D`(삭제) |
  | `stage` | 실패 단계 | `direct`(동기화 없는 직접 저장), `afterCommit`(커밋 후 저장), `schedule`(예약 실패) |

> 엔티티 식별자(PK)와 실패 원인은 태그가 아니라 ERROR 로그(`[감사로그 기록 실패] ...`)에만 남깁니다.

## 조회 (관리자 전용)

Actuator `metrics` 엔드포인트는 `SecurityConfig`에서 관리자(`ROLE_ADMIN`) 전용으로 제한됩니다.

```text
GET /actuator/metrics/audit.log.write.failure
```

- 전체 누적 실패 건수(모든 태그 합산)를 반환합니다.
- 단계별로 좁혀 보려면 `tag` 쿼리로 필터링합니다.

```text
GET /actuator/metrics/audit.log.write.failure?tag=stage:afterCommit
GET /actuator/metrics/audit.log.write.failure?tag=entity:Bprojm&tag=chgTp:U
```

- `/actuator/health`는 공개(헬스체크)이며, 그 외 Actuator 엔드포인트는 관리자 인증이 필요합니다.

## 경보 기준

- **경보 조건**: 5분 증가량 > 0 (즉, 새로운 감사 실패가 1건이라도 발생하면 경보)
- 감사 실패는 정상 상태에서 0이 유지되어야 하므로, 증가 자체를 이상 신호로 취급합니다.

## 초동 조치

1. **원 업무 성공 여부 확인**: 실패 로그의 `entity`/식별자로 해당 업무 데이터가 정상 저장됐는지 확인합니다.
   (감사 실패는 원 업무를 롤백하지 않으므로 원 업무는 성공했을 수 있습니다.)
2. **감사 저장 경로 점검**: 대상 로그 테이블·시퀀스 존재 여부, 계정 권한, 제약조건(NOT NULL·유니크) 위반 여부를 확인합니다.
3. **누락 범위 산정**: 실패 시각·엔티티·변경유형(`entity`/`chgTp`/`stage`)으로 누락된 감사 이력 범위를 산정하고, 필요 시 별도 데이터 조치로 보정합니다.

## 주의

- 외부 모니터링 계정에 **ADMIN JWT를 발급해 상시 사용하지 않습니다.** 관리자 토큰이 모니터링 경로로 유출되면 관리자 권한 전체가 노출됩니다.
- 외부 수집은 운영망 전용 관리 포트 또는 내부 프록시로 접근 범위를 제한하고, 인증·네트워크 경계를 별도로 통제합니다.
